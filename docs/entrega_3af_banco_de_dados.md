## 1. Introdução e Explicação do Projeto

O **SemBarreiras (MobiLivre — ADEFAL)** é um sistema integrado voltado à autonomia, segurança, mobilidade urbana acessível e assistência em saúde de **Pessoas com Deficiência Física (PCD)** atendidas pela **ADEFAL** (Associação dos Deficientes Físicos de Alagoas) e seus cuidadores ou tutores legais.

A arquitetura do banco de dados relacional foi modelada no **PostgreSQL** para suportar cinco módulos funcionais integrados:
1. **Contas, Acessibilidade Motora e Vínculos:** Cadastro de titulares PCD e cuidadores, preferências de acessibilidade motora (tamanho de área de toque e alto contraste), vínculo autorizado por código OTP de 6 dígitos e log imutável de auditoria de segurança.
2. **Emergência e Botão de Pânico:** Gestão de até 3 contatos prioritários de emergência (1ª, 2ª e 3ª prioridade) e registro geolocalizado de disparos de pânico com fallback para SMS.
3. **Transporte Urbano Acessível:** Cadastro de linhas de ônibus, pontos de parada acessíveis e telemetria de veículos adaptados com elevador/rampa funcional ativa para cálculo de tempo estimado de chegada (ETA).
4. **Agendamentos e Transporte Hospitalar ADEFAL:** Grade de vagas médicas e de reabilitação, marcação de consultas com protocolo único e QR Code assinado criptograficamente (`HMAC-SHA256`), além de reserva de vans adaptadas porta a porta.
5. **Empréstimo de Equipamentos Ortopédicos:** Solicitação de cadeiras de rodas, órteses e muletas com validação antropométrica (largura do quadril, estatura e peso), anexo de laudo médico e linha do tempo de triagem clínica.

## 3. Critério 1 (1,0 Ponto): Criação das Tabelas (DDL) com as 4 Integridades

As **4 Integridades Relacionais** foram implementadas da seguinte forma:
- **Integridade de Entidade:** Todas as tabelas possuem chave primária única e não nula (`"id" bigint NOT NULL PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY`).
- **Integridade Referencial:** Chaves estrangeiras explícitas (`FOREIGN KEY ... REFERENCES`) com regras `ON DELETE RESTRICT` (protegendo históricos clínicos, consultas e auditoria contra exclusão acidental) e `ON DELETE CASCADE` (para entidades dependentes).
- **Integridade de Domínio:** Tipagem estrita (`numeric(5,2)`, `double precision`, `smallint`, `date`, `time`, `timestamp with time zone`), colunas `NOT NULL`, valores `DEFAULT` e restrições `CHECK` validando limites clínicos (quadril 15..120 cm, altura 40..240 cm, peso 5..300 kg), prioridades (1 a 3) e ocupação de vans.
- **Integridade Definida pelo Usuário (Negócio):** Restrições `UNIQUE` em CPF, e-mail e protocolos, além de `CONSTRAINT` compostas impedindo vínculos duplicados (`cuidador_id, titular_pcd_id`), auto-vínculo (`cuidador_id <> titular_pcd_id`) e conflito de agenda médica (`unidade, profissional, data, horario`).

## 5. Critério 3 (1,0 Ponto): Criação de uma Trigger no Banco de Dados

A trigger `trg_proteger_cpf_e_auditar_usuario` garante diretamente no SGBD a imutabilidade do CPF após o cadastro e automatiza a gravação de logs de auditoria em bloqueios ou mudanças de status cadastral:

```sql
CREATE OR REPLACE FUNCTION fn_proteger_cpf_e_auditar_usuario()
RETURNS TRIGGER
LANGUAGE plpgsql
AS $$
BEGIN
    -- 1. Imutabilidade do CPF (exceto mascaramento de inativação LGPD status = 3)
    IF NEW.cpf <> OLD.cpf AND NEW.status_cadastro <> 3 THEN
        RAISE EXCEPTION 'Violação de integridade (RS007): O CPF do usuário (%) é imutável após o cadastro.', OLD.cpf;
    END IF;

    -- 2. Auditoria automática de bloqueio temporário por tentativas falhas
    IF NEW.bloqueado_ate IS DISTINCT FROM OLD.bloqueado_ate AND NEW.bloqueado_ate IS NOT NULL THEN
        INSERT INTO "contas_logauditoriaconta" ("evento", "detalhes", "ip", "criado_em", "usuario_id")
        VALUES (
            'TRIGGER_BLOQUEIO_CONTA',
            'Bloqueio temporário detectado pelo SGBD até ' || TO_CHAR(NEW.bloqueado_ate, 'DD/MM/YYYY HH24:MI:SS'),
            'SGBD_TRIGGER',
            CURRENT_TIMESTAMP,
            NEW.id
        );
    END IF;

    -- 3. Auditoria automática de mudança de status cadastral
    IF NEW.status_cadastro <> OLD.status_cadastro THEN
        INSERT INTO "contas_logauditoriaconta" ("evento", "detalhes", "ip", "criado_em", "usuario_id")
        VALUES (
            'TRIGGER_MUDANCA_STATUS_CONTA',
            'Status cadastral alterado de ' || OLD.status_cadastro || ' para ' || NEW.status_cadastro,
            'SGBD_TRIGGER',
            CURRENT_TIMESTAMP,
            NEW.id
        );
    END IF;

    RETURN NEW;
END;
$$;

DROP TRIGGER IF EXISTS trg_proteger_cpf_e_auditar_usuario ON "contas_usuario";

CREATE TRIGGER trg_proteger_cpf_e_auditar_usuario
BEFORE UPDATE ON "contas_usuario"
FOR EACH ROW
EXECUTE FUNCTION fn_proteger_cpf_e_auditar_usuario();
```

## 6. Critério 4 (1,0 Ponto): Criação de uma View no Banco de Dados

A view `vw_painel_consultas_e_transporte_adefal` unifica os dados de consultas, perfil PCD, especialidade/unidade da ADEFAL e logística de vans adaptadas:

```sql
CREATE OR REPLACE VIEW vw_painel_consultas_e_transporte_adefal AS
SELECT
    c.id AS consulta_id,
    c.protocolo AS protocolo_consulta,
    c.status AS status_consulta,
    c.assinatura_qr,
    u.cpf AS paciente_cpf,
    u.nome_completo AS paciente_nome,
    u.telefone AS paciente_telefone,
    p.tipo_deficiencia,
    p.equipamentos_apoio,
    v.especialidade,
    v.unidade AS unidade_adefal,
    v.profissional AS profissional_responsavel,
    v.data AS data_consulta,
    v.horario AS horario_consulta,
    st.id AS solicitacao_transporte_id,
    st.endereco_embarque,
    st.horario_apanhe_previsto,
    st.precisa_acompanhante,
    st.status AS status_transporte,
    f.veiculo_identificacao AS van_adaptada,
    f.motorista AS motorista_van
FROM "agendamentos_consulta" c
INNER JOIN "contas_usuario" u
    ON u.id = c.paciente_pcd_id
LEFT JOIN "contas_perfilpcd" p
    ON p.usuario_id = u.id
INNER JOIN "agendamentos_vagaagendaadefal" v
    ON v.id = c.vaga_id
LEFT JOIN "agendamentos_solicitacaotransporte" st
    ON st.consulta_id = c.id
LEFT JOIN "agendamentos_vagafrotaadaptada" f
    ON f.id = st.frota_id;
```
