1. INTRODUÇÃO E EXPLICAÇÃO DO PROJETO
--------------------------------------------------------------------------------
O projeto SemBarreiras (MobiLivre — ADEFAL) é um sistema integrado voltado à
autonomia, segurança, mobilidade urbana acessível e assistência em saúde de
Pessoas com Deficiência Física (PCD) atendidas pela ADEFAL (Associação dos
Deficientes Físicos de Alagoas) e seus cuidadores ou tutores legais.

A arquitetura do banco de dados relacional foi modelada no PostgreSQL para
suportar cinco módulos funcionais integrados:
  1) Contas, Acessibilidade Motora e Vínculos: Cadastro de titulares PCD e
     cuidadores, preferências de acessibilidade motora (tamanho de toque e alto
     contraste), vínculo autorizado por código OTP de 6 dígitos e log imutável
     de auditoria de segurança.
  2) Emergência e Botão de Pânico: Gestão de até 3 contatos prioritários de
     emergência (1ª, 2ª e 3ª ordem) e registro geolocalizado de disparos de
     pânico com fallback para SMS.
  3) Transporte Urbano Acessível: Cadastro de linhas de ônibus, pontos de
     parada acessíveis e telemetria de veículos adaptados com elevador/rampa
     funcional ativa para cálculo de tempo estimado de chegada (ETA).
  4) Agendamentos e Transporte Hospitalar ADEFAL: Grade de vagas médicas e de
     reabilitação, marcação de consultas com protocolo único e QR Code assinado
     criptograficamente (HMAC-SHA256), além de reserva de vans adaptadas.
  5) Empréstimo de Equipamentos Ortopédicos: Solicitação de cadeiras de rodas,
     órteses e muletas com validação antropométrica (quadril, estatura e peso),
     anexo de laudo médico e linha do tempo de triagem clínica.

3. CRITÉRIO 1 (1,0 PONTO): CRIAÇÃO DAS TABELAS (DDL) COM AS 4 INTEGRIDADES
================================================================================
Como as 4 Integridades Relacionais foram garantidas no DDL abaixo:
  - Integridade de Entidade: Todas as tabelas possuem chave primária única e
    não nula ("id" bigint NOT NULL PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY).
  - Integridade Referencial: Chaves estrangeiras explícitas (FOREIGN KEY ...
    REFERENCES) com regras ON DELETE RESTRICT (protegendo históricos clínicos,
    consultas e auditoria contra exclusão acidental) e ON DELETE CASCADE (para
    entidades dependentes).
  - Integridade de Domínio: Tipagem estrita (numeric(5,2), double precision,
    smallint, date, time, timestamp with time zone), colunas NOT NULL, valores
    DEFAULT e restrições CHECK validando limites clínicos (quadril 15..120 cm,
    altura 40..240 cm, peso 5..300 kg), prioridades (1 a 3) e ocupação de vans.
  - Integridade Definida pelo Usuário (Negócio): Restrições UNIQUE em CPF,
    e-mail e protocolos, além de constraints compostas impedindo vínculos
    duplicados (cuidador_id, titular_pcd_id), auto-vínculo (cuidador <> titular)
    e conflito de agenda médica (unidade, profissional, data, horario).

5. CRITÉRIO 3 (1,0 PONTO): CRIAÇÃO DE UMA TRIGGER NO BANCO DE DADOS
================================================================================
Explicação:
A trigger "trg_proteger_cpf_e_auditar_usuario" atua antes de qualquer UPDATE na
tabela "contas_usuario". Ela cumpre duas regras críticas de segurança:
  1) Impede que o CPF de um usuário ativo seja alterado após o cadastro;
  2) Insere automaticamente um registro de auditoria em "contas_logauditoriaconta"
     sempre que a conta sofrer bloqueio temporário ou mudança de status cadastral.

-- [TRECHO SQL DA FUNÇÃO E TRIGGER] --

CREATE OR REPLACE FUNCTION fn_proteger_cpf_e_auditar_usuario()
RETURNS TRIGGER
LANGUAGE plpgsql
AS $$
BEGIN
    -- 1. Imutabilidade do CPF (exceto mascaramento de inativação LGPD status = 3)
    IF NEW.cpf <> OLD.cpf AND NEW.status_cadastro <> 3 THEN
        RAISE EXCEPTION 'Violação de integridade (RS007): O CPF do usuário (%) é imutável após o cadastro.', OLD.cpf;
    END IF;

    -- 2. Auditoria automática de bloqueio temporário por tentativas falhas
    IF NEW.bloqueado_ate IS DISTINCT FROM OLD.bloqueado_ate AND NEW.bloqueado_ate IS NOT NULL THEN
        INSERT INTO "contas_logauditoriaconta" ("evento", "detalhes", "ip", "criado_em", "usuario_id")
        VALUES (
            'TRIGGER_BLOQUEIO_CONTA',
            'Bloqueio temporário detectado pelo SGBD até ' || TO_CHAR(NEW.bloqueado_ate, 'DD/MM/YYYY HH24:MI:SS'),
            'SGBD_TRIGGER',
            CURRENT_TIMESTAMP,
            NEW.id
        );
    END IF;

    -- 3. Auditoria automática de mudança de status cadastral
    IF NEW.status_cadastro <> OLD.status_cadastro THEN
        INSERT INTO "contas_logauditoriaconta" ("evento", "detalhes", "ip", "criado_em", "usuario_id")
        VALUES (
            'TRIGGER_MUDANCA_STATUS_CONTA',
            'Status cadastral alterado de ' || OLD.status_cadastro || ' para ' || NEW.status_cadastro,
            'SGBD_TRIGGER',
            CURRENT_TIMESTAMP,
            NEW.id
        );
    END IF;

    RETURN NEW;
END;
$$;

6. CRITÉRIO 4 (1,0 PONTO): CRIAÇÃO DE UMA VIEW NO BANCO DE DADOS
================================================================================
Explicação:
A view "vw_painel_consultas_e_transporte_adefal" consolida os dados de 6 tabelas
("agendamentos_consulta", "contas_usuario", "contas_perfilpcd",
"agendamentos_vagaagendaadefal", "agendamentos_solicitacaotransporte" e
"agendamentos_vagafrotaadaptada"), permitindo que a recepção e a triagem da
ADEFAL consultem agendamentos, validação de QR Code e logística de vans
adaptadas sem expor dados sensíveis de senha ou anexos médicos.

-- [TRECHO SQL DA VIEW] --

CREATE OR REPLACE VIEW vw_painel_consultas_e_transporte_adefal AS
SELECT
    c.id AS consulta_id,
    c.protocolo AS protocolo_consulta,
    c.status AS status_consulta,
    c.assinatura_qr,
    u.cpf AS paciente_cpf,
    u.nome_completo AS paciente_nome,
    u.telefone AS paciente_telefone,
    p.tipo_deficiencia,
    p.equipamentos_apoio,
    v.especialidade,
    v.unidade AS unidade_adefal,
    v.profissional AS profissional_responsavel,
    v.data AS data_consulta,
    v.horario AS horario_consulta,
    st.id AS solicitacao_transporte_id,
    st.endereco_embarque,
    st.horario_apanhe_previsto,
    st.precisa_acompanhante,
    st.status AS status_transporte,
    f.veiculo_identificacao AS van_adaptada,
    f.motorista AS motorista_van
FROM "agendamentos_consulta" c
INNER JOIN "contas_usuario" u
    ON u.id = c.paciente_pcd_id
LEFT JOIN "contas_perfilpcd" p
    ON p.usuario_id = u.id
INNER JOIN "agendamentos_vagaagendaadefal" v
    ON v.id = c.vaga_id
LEFT JOIN "agendamentos_solicitacaotransporte" st
    ON st.consulta_id = c.id
LEFT JOIN "agendamentos_vagafrotaadaptada" f
    ON f.id = st.frota_id;

7. CRITÉRIO 5 (1,0 PONTO): CRIAÇÃO DE CONTAS E PERMISSÕES DE ACESSO (DCL)
================================================================================
Explicação:
Foram criadas 3 roles seguindo o Princípio do Menor Privilégio e a LGPD:
  1) role_app_sembarreiras: Conta da aplicação com SELECT, INSERT e UPDATE, mas
     com REVOKE DELETE/UPDATE nas tabelas de log de auditoria e ocorrências de
     pânico para garantir que o histórico seja imutável.
  2) role_triagem_adefal: Conta da equipe clínica para gerenciar vagas, frota e
     solicitações de empréstimo de equipamentos.
  3) role_portaria_adefal: Conta restrita da portaria com acesso EXCLUSIVO de
     leitura (SELECT) à View "vw_painel_consultas_e_transporte_adefal" para
     conferência de comprovantes/QR Code, sem acesso às tabelas de laudos.

-- [TRECHO SQL DE CONTAS E PERMISSÕES - DCL] --

DO $$
BEGIN
    IF NOT EXISTS (SELECT 1 FROM pg_roles WHERE rolname = 'role_app_sembarreiras') THEN
        CREATE ROLE role_app_sembarreiras WITH LOGIN PASSWORD 'AppSemBarreiras#2026!';
    END IF;

    IF NOT EXISTS (SELECT 1 FROM pg_roles WHERE rolname = 'role_triagem_adefal') THEN
        CREATE ROLE role_triagem_adefal WITH LOGIN PASSWORD 'TriagemAdefal#2026!';
    END IF;

    IF NOT EXISTS (SELECT 1 FROM pg_roles WHERE rolname = 'role_portaria_adefal') THEN
        CREATE ROLE role_portaria_adefal WITH LOGIN PASSWORD 'PortariaAdefal#2026!';
    END IF;
END
$$;

GRANT USAGE ON SCHEMA public TO role_app_sembarreiras, role_triagem_adefal, role_portaria_adefal;

-- Permissões da Aplicação Web (com bloqueio de exclusão em tabelas de auditoria/pânico)
GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO role_app_sembarreiras;
GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO role_app_sembarreiras;
REVOKE DELETE, UPDATE ON "contas_logauditoriaconta" FROM role_app_sembarreiras;
REVOKE DELETE ON "emergencia_ocorrenciapanico" FROM role_app_sembarreiras;

-- Permissões da Equipe de Triagem e Almoxarifado da ADEFAL
GRANT SELECT ON "contas_usuario", "contas_perfilpcd", "vw_painel_consultas_e_transporte_adefal" TO role_triagem_adefal;
GRANT SELECT, INSERT, UPDATE ON
    "agendamentos_vagaagendaadefal",
    "agendamentos_vagafrotaadaptada",
    "agendamentos_consulta",
    "agendamentos_solicitacaotransporte",
    "equipamentos_solicitacaoequipamento",
    "equipamentos_eventolinhatempoequipamento"
TO role_triagem_adefal;
GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO role_triagem_adefal;

-- Permissões Restritas da Portaria ADEFAL (Apenas leitura na View de comprovantes)
REVOKE ALL ON ALL TABLES IN SCHEMA public FROM role_portaria_adefal;
GRANT SELECT ON vw_painel_consultas_e_transporte_adefal TO role_portaria_adefal;
